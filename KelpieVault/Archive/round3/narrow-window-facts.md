## 2. Resize path
- `Sources/Heeler/Terminal/TerminalScreenView.swift:133` `onSizeChanged` callback property; wired through `HerdrClientView.swift:30-31` `screen.onSizeChanged = { cols, rows in store.viewDidResize(cols: cols, rows: rows) }`.
- `Sources/Heeler/Client/HerdrClientStore.swift:83-85` `viewDidResize(cols:rows:)` forwards to `terminal.viewDidResize(cols:rows:)`.
- Delivery chain inside the view: `TerminalScreenView.swift:440-511` `receiveResize` → `deliverSize` → `onSizeChanged?(...)`. Grid metrics (incl. cell pixel size) are read in `terminalDidResize(_:)` at `TerminalScreenView.swift:2340-2356` (`GhosttyTerminal`'s `TerminalSurfaceGridResizeDelegate`; `size.cellWidthPixels`/`cellHeightPixels` divided by `nativeScale`).
- Wire path: `Sources/Heeler/Transport/TerminalAttach.swift:209-210` `resize(cols:rows:)` → `enqueueReliable(.resize(...), discardingPendingScroll: false)`; drained in `TerminalAttach.swift:282-293` (`pump`) which calls the `resize` closure — wired in `HeelerSSHTransport.swift:2319-2320` to `channel.resize(columns:rows:timeout:)`. That reaches `Packages/HeelerSSH/Sources/HeelerSSH/SSHPTYChannel.swift:36-38` → `SessionDriver.swift:624-647` `libssh2_channel_request_pty_size_ex`. This is a raw PTY winsize change over the exec/PTY channel, not a herdr JSON-API `pane.resize`-style call (no `TIOCSWINSZ` string found; libssh2 issues the SSH `window-change` channel request directly).
- **Debounce**: none, for ordinary window resize. `TerminalAttach`'s reliable-input queue (`TerminalAttach.swift:126,138,167,209-210,257-274`) explicitly coalesces only touch-scroll input (`pendingScroll`); resize items are appended individually and drained FIFO one at a time (`pump`, `TerminalAttach.swift:275-296`), each awaiting its own `resize(cols:rows:)` RPC before the next queue item runs. The one filtering mechanism present, `isSizeReportCurrent` (`TerminalScreenView.swift:340,452,948`), drops a delivered grid report only if it no longer matches the *current* live grid size — it is a staleness check, not a time-based debounce. The freeze/thaw machinery at `TerminalScreenView.swift:293-496` (`defersSizeReports`, `discardsResizeReportsThrough`, `gridReportPhase`) exists specifically for **keyboard-transition** grid freezes, not for divider drags. So during a live Split View divider drag, Ghostty's UIKit layout will emit a resize callback per layout pass; each becomes its own reliable queue entry and its own serialized PTY resize RPC over SSH — no throttling was found for this path. Confirms `KelpieVault/Open items.md:26` flags a related-but-different concern about `.detailOnly`/sidebar interaction, not this resize-rate concern (no existing note found on resize-rate/drag specifically).
