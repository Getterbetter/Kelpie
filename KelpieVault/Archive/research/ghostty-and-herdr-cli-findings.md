## A2. Hardware keyboard

This means Enter/Return, Ctrl+letter, arrows, Esc, Tab are ALL encoded by the Ghostty/Zig core itself, not by Swift — Return -> GHOSTTY_KEY_ENTER (mapped at TerminalHardwareKeyRouter.swift:88 UIKit HID 0x28, and AppKit keycode 0x24 at line ~171), Esc -> GHOSTTY_KEY_ESCAPE (0x29 UIKit / 0x35 AppKit), Tab -> GHOSTTY_KEY_TAB (0x2B UIKit / 0x30 AppKit), all 4 arrows mapped (0x4F-0x52 UIKit / 0x7B-0x7E AppKit). CR-vs-LF encoding for Enter is a core/Zig-side policy, UNCONFIRMED in this Swift package (not overridden here).
- Ctrl+letter on iOS: UIKit's UITextInput/emacs bindings would normally swallow Ctrl+letter chords, so UITerminalView+Keyboard.swift:79-113 explicitly registers `UIKeyCommand`s for ctrl+[a-z0-9 and punctuation] with `wantsPriorityOverSystemBehavior = true` (comment: "the same route Blink and SwiftTerm take") — file: Sources/GhosttyTerminal/Platform/UIKit/UITerminalView+Keyboard.swift:79-116 (`controlKeyCommandInputs`, `controlKeyCommands`, `keyCommands` override, `handleControlKeyCommand`).

## B4. Exact CLI to attach the full client to an already-running server

Top-level clap spec at /private/tmp/.../herdr/repo/src/cli/spec.rs:9-46 (`pub(super) fn command()`): bare `herdr` is the DEFAULT launch command (no subcommand named "attach" needed) — it launches/attaches the full interactive client (workspaces, tabs, panes, sidebar) to the local server, auto-starting the server if not running (server/session logic in src/session.rs / src/server/*). Flags on the root command (spec.rs:13-27):
- `--session <NAME>` — use or create a named persistent session (spec.rs:14; also src/main.rs:588 help text)
- `--remote <TARGET>` — attach through SSH to a remote Herdr server (spec.rs:15; src/main.rs:681)
- `--remote-keybindings <local|server>` — local vs server keybindings for remote attach (spec.rs:16-19)
- `--handoff` — opt into live handoff for update/remote attach (spec.rs:21)
- `--default-config`, `--skill`, `-V/--version` (spec.rs:22-29)
No `--server`/socket-path flag exists on the bare command (confirmed by grep of main.rs help block, lines 580-600, and cli/spec.rs — only `HERDR_SOCKET_PATH`-style env override at the API layer, src/api/server.rs:1055-1061 test `socket_path_prefers_explicit_env_override`). No explicit "read-only" attach flag found on the root command.
Named-session attach subcommand: `herdr session attach <name>` (src/cli/spec.rs:730-737, session_command()) — also launches the full client, scoped to that named session.
Per docs (herdr.dev/docs/cli-reference, fetched): `herdr` = attach to default session; `herdr --session <name>` = named session; `herdr --remote <host>` = SSH-based attach with local keybindings by default. For an SSH session already on the target machine (the herdr server already running there), the correct invocation is simply `herdr` (or `herdr --session <name>` if the server manages multiple named sessions) — NOT `herdr --remote`, which is for attaching from a different machine over SSH.

Contrast — `herdr agent attach <target> [--takeover]` (src/cli/spec.rs:394-399, and dispatch at src/cli.rs:122 `"agent" => agent::run_agent_command`): this is a narrower, single-pane/agent-terminal attach (no full client UI, no sidebar/workspaces) — "Attach directly to an agent terminal." `--takeover` here forcibly takes control of that one agent pane away from any other attached viewer. There is an analogous `herdr terminal attach <terminal_id> [--takeover]` (src/cli.rs:530-538, `parse_attach_target`, src/cli.rs:718-737) and `herdr terminal session control <target> [--takeover] [--cols N] [--rows N]` (src/cli/spec.rs:692-712) for raw terminal-stream control — all distinct from the full-client `herdr` launch.

## B6. Hyperlinks in herdr

herdr DOES pass through / detect OSC 8 hyperlinks from child panes and has its OWN URL click-handling (this is native to herdr's TUI, separate from any embedded Ghostty use):
- Hit-testing a clicked cell against hyperlinks: `runtime.visible_hyperlinks(area)` (src/app/actions.rs:1122-1134, function `url_at_runtime_cell`) checks OSC-8-tagged hyperlinks first, THEN falls back to plain-text URL pattern matching in the visible line (`url_at_column`) if no OSC 8 link is at that cell — src/app/actions.rs:1108-1150.
- Click dispatch: `ClientShellAction::OpenSafeWebUrl(String)` (src/client/shell/state.rs:301) is produced in src/client/shell/actions.rs:755-761 after a server round-trip returns `ResponseResult::PaneLinkActivated { url, handled }`; only fires `OpenSafeWebUrl` when `handled == false` and `crate::app::actions::safe_web_url(&url)` passes (only `http://`/`https://` URLs allowed — src/app/actions.rs:1157-1159, function `safe_web_url`).
- Actually opening: src/client/shell_runtime.rs:38-44 (`dispatch_client_shell_actions`, case `ClientShellAction::OpenSafeWebUrl`) calls `crate::platform::open_url(&url)`, platform-specific: macOS spawns `open <url>` (src/platform/macos.rs:526-533), Linux spawns `xdg-open <url>` (src/platform/linux.rs:470-476), Windows has its own impl (src/platform/windows.rs:2067), and a no-op fallback exists (src/platform/fallback.rs:233).
- No dedicated keybinding/config key for "open URL" was found in src/config/keybinds.rs or src/config/model.rs (grep for hyperlink/open_link/OpenLink returned nothing there) — it is purely mouse-click-triggered, matching the docs fetch (herdr.dev/docs/keyboard) which likewise found no URL-opening keybinding documented.
