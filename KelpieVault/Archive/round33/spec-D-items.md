Letter: **D**. Read `spec-common.md` first; it governs worktree, build lock, paths and reporting. No cherry-picks here: this is Kelpie code. Full item text is in `KelpieVault/Open items.md`. One commit per item, each with a unit test, message `<area>: <what> (Open item N)`.

**49. A reconnect inside the banner's 3 s hold loses the banner.** Diagnosis in `KelpieVault/Archive/round30/item19-diagnosis.md` ("Left undone"). A status change starts a 3 s hold before the in-app banner; a connection drop inside that window makes `HostConsoleProjection.invalidateSnapshot()` empty `agentsByPane`, the empty list reaches `agentsDidChange` and cancels the hold, and the returning snapshot carries the same status as the preserved baseline, so nothing reschedules it. Fix: an emptied snapshot (invalidation) must not cancel a pending transition; when the pane comes back with the same status the hold re-arms (or simply keeps running), and a pane that comes back with a different status, or does not come back, is handled as today. Test the drop-inside-the-hold sequence and the pane-gone case with the existing banner/router test seams (find the suites that cover the round-30 fix).

**53. `agent.rename` refuses a pending launch with `agent_launch_pending` (herdr 0.9.1).** First find every path that calls `agent.rename`, and whether any of them renames right after `agent.start` (the new-agent form giving a name would make this common, not rare). Then: retry the rename on `agent_launch_pending` with a bounded wait (about 1 s steps, up to about 10 s, cancellable), and if it still refuses, surface a friendly message ("The agent is still starting. Try renaming it again in a moment.") instead of herdr's raw text, through whatever error-message mapping the app already uses for herdr error codes. Test both outcomes with the scripted transport.

**52. Orphaned `notifications.json.tmp-<uuid>` files on the Host.** `HeelerSSHTransport.performNotificationFileReplace` writes a temporary file over SFTP and renames it; a connection dying mid-write leaves the temp file. After a **successful** replace, sweep sibling files matching `notifications.json.tmp-*` whose modification time is older than one hour (never the one just written, never anything else), best effort: a sweep failure is ignored and never fails the replace. Test the name matching and age rule as a pure function, plus the sweep being invoked only after success if the transport has a seam for it.
