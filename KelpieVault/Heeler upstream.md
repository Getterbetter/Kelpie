# Heeler upstream

**Heeler** — `github.com/ZingerLittleBee/Heeler`. A native iOS companion app for [[herdr]]: an agent console over SSH rather than a terminal app. Apache-2.0. ~290 stars and 31 open issues when scouted on 2026-09-10; the tree moves daily.

By **ZingerLittleBee**, a third-party developer — **not** the author of herdr. Announced on r/herdr around 2026-08-25 ("I built an iOS companion for herdr because I kept SSHing into my Mac just to check on agents"). The thread was small: four comments, one real feature request (jump-to-previous-entry and jump-to-bottom, since shipped), and the developer asking that future requests come in as GitHub issues. iPad was never mentioned, by anyone, anywhere in it.

Git remote in Kelpie: **`upstream`** only. There is no `origin`, and nothing has ever been pushed.

## What Heeler gives Kelpie for free

The whole lower half of the app. SwiftUI on iOS 18+, XcodeGen project generation, libssh2/OpenSSL transport in `Packages/HeelerSSH`, direct-streamlocal onto herdr's socket, PTY attach, a libghostty terminal surface, Keychain key handling with on-device Ed25519 generation, TOFU host-key policy, jump hosts, 30 terminal themes, the agent console, image and file staging, encrypted push, Live Activities and the Dynamic Island, and the pairing plugin. See [[Architecture]].

It also ships three sibling deliverables in the same repo: `plugin/` (the herdr plugin, Node), `relay/` (the Push Relay, a Cloudflare Worker), and `landing/` (the marketing site).

## How Kelpie differs

| | Heeler | Kelpie |
| --- | --- | --- |
| Devices | iPhone only (`TARGETED_DEVICE_FAMILY "1"`; README says "iPad planned") | iPhone + iPad (`"1,2"`), indirect input events enabled |
| Root screen | The native agent console | herdr's own TUI, full-screen (`HerdrClientRootView`) |
| The console | Is the app | A `fullScreenCover` behind a floating `ellipsis.circle` |
| Attach target | `herdr agent attach` / `herdr terminal attach` | plus bare `herdr` — the full client |
| Right click | None (Ghostty's iPadOS copy menu) | Reported to herdr from trackpad, mouse and touch long-press |
| Trackpad scroll | None on iPadOS | Scroll-type pan feeding the same scroll path as a finger |
| URL taps | Nothing on iOS | Detected client-side, opened in the iPadOS default browser |
| Keyboard mode | User choice in Settings | Automatic from hardware-keyboard presence (default) |
| Default font | 8 pt | 12 pt on iPad, 8 pt elsewhere |
| Attach env | PATH + socket | plus `COLORTERM=truecolor` and a `LANG` default |
| Ghostty | Remote SPM dependency | Vendored under `Packages/GhosttyTerminal` |
| Identity | `dev.bybee.heeler`, team `9VM4RM39R3` | `TME.Kelpie`, team `8JQWBQKEXX`, app group `group.TME.Kelpie.shared` |
| Push | Works, via the hosted relay | **Does not work** — see below |

Module name, target names, `Heeler.xcodeproj` and the `Heeler` scheme are deliberately unchanged; only `PRODUCT_NAME`/`CFBundleDisplayName` say Kelpie. Reasoning in [[Decisions]].

## Rebase strategy

Upstream moves fast — daily commits, a live App Store/TestFlight release train. Kelpie's changes are deliberately shaped to survive that:

- **Nothing in `Packages/`, `plugin/`, `relay/` or `landing/` is edited.** The one exception is the vendored `Packages/GhosttyTerminal`, which is an addition, not a modification.
- Round 1's input work lives entirely in overrides on `HeelerTerminalView` — Ghostty's `open` members — plus small additions to `TerminalMouseReporting` / `TerminalTouchScroll`.
- Round 2's work is almost all **new files** under `Sources/Heeler/Client/` plus `TerminalLinkDetector.swift`. The edits to existing files are narrow: `ContentView.swift`'s root, one optional `onClose` on `ConsoleView`, a `.client` case in the attach builder, an `.automatic` case in the input-mode settings, an idiom-aware default in `TerminalZoomSettings`.
- The conflict-prone files are `project.yml` and the committed `Heeler.xcodeproj` (regenerated, so take upstream's and re-run `xcodegen generate`), `CHANGELOG.md` (Kelpie's section sits above `[Unreleased]`) and `CLAUDE.md` (Kelpie's section sits at the top).

First rebase done 2026-09-11 (round 7, onto `375267c`): only `CHANGELOG.md` conflicted, twice, at the `## [Unreleased]` anchor; `Heeler.xcodeproj` and `project.yml` had not moved upstream so no regen commit was needed. Plan and summary in `Archive/round7/`. Periodic rebase stays [[Open items|an open item]]. A pull request upstream for the iPad work is Anthony's call and deliberately deferred.

## Push and the relay — why notifications do not work in Kelpie

The path a push takes upstream:

1. On the Mac, herdr fires the plugin's notify hook on `pane.agent_status_changed` when an agent goes Blocked or Done. The plugin encrypts the notification with that Host's symmetric **Notification Key** (generated by the app and copied over SSH) and POSTs `{token, env, envelope, collapse}` to the relay's `POST /push`.
2. The **relay** — `relay/src/worker.js`, a dependency-free Cloudflare Worker, hosted at `https://heeler-apns.bybee.dev` — signs an APNs provider JWT and forwards the still-opaque ciphertext to Apple. It is stateless on purpose: no accounts, no database, no queue, and it never sees a Notification Key.
3. APNs delivers; the app's Notification Service Extension decrypts the envelope from the shared Keychain and rewrites the alert into the real title and body.

**Why it breaks for Kelpie.** The hosted relay pins `APNS_TOPIC = dev.bybee.heeler` and signs with the upstream developer's `.p8` under team `9VM4RM39R3`. APNs only delivers a push whose topic matches the receiving app's bundle ID and whose key is authorised for that app's team. A push aimed at `TME.Kelpie` / team `8JQWBQKEXX` sent with topic `dev.bybee.heeler` is rejected outright. Nothing on the app side can fix this; the app already exposes a "Custom Push Relay" setting, but there is nothing to point it at yet.

**The two ways out:**

- **Deploy our own `relay/`** — a Cloudflare Worker with Anthony's own APNs `.p8`, `APNS_TEAM_ID = 8JQWBQKEXX`, `APNS_TOPIC = TME.Kelpie` — and point the app (or the in-app custom relay URL) and the plugin's default at it. **Mandatory for any App Store build**: the APNs key cannot ship to users' Macs.
- **For a personal build only**, the herdr plugin on the mini could call APNs directly and skip the relay entirely, since the key would never leave Anthony's machine.

Cost is effectively zero — Cloudflare's free tier, and the APNs key is free with the developer account. This is outward-facing work and needs Anthony's explicit yes; it is item 3 in [[Open items]].
